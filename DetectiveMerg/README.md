# DetectiveMerg — слияние vs мультиагент на взаимозависимой задаче

Главный эксперимент проекта. Проверяет вопрос, которого нет в литературе по model merging:

> Заменяет ли training-free слияние двух специалистов **мультиагентную систему** на
> **взаимозависимой** задаче, где навыки нужно **сцеплять**, — и что происходит с самими навыками?

**Короткий ответ (Qwen2.5-3B):** нет. Мультиагент решает полную цепь в ~53–60%, а **все
навык-агностичные слияния (linear, TIES, DARE, DELLA) — 0%**, теряя узкий навык. Единственный
метод, сохраняющий оба навыка (**EMR**), делает это лишь как **task-conditional выбор маски =
маршрутизация в маскировке**. **Co-existence ≠ integration.**

---

## Идея и дизайн
- **Две специализированные модели** = два LoRA-адаптера на одной базе `Qwen2.5-3B-Instruct`:
  `detective` (криминалистическая дедукция) и `medic` (судебная токсикология).
- **Знания реальные, но узкие/редкие** (cherry-red кожа → CO → доступ у механика; угол брызг →
  высокий рост и т.п.) — база знает их лишь частично.
- **Квест из 3 взаимозависимых шагов**, логика по 7 подозреваемым (4 имеют нужную профессию,
  4 — нужный признак, пересечение = 1 виновный): без **обоих** фактов виновный не определяется.
  - **Q1** (детектив): улика → атрибут виновного.
  - **Q2** (медицина, через **роутинг** к медику): признак тела → яд + профессия с доступом.
  - **Q3** (детектив): пересечь оба факта по списку подозреваемых → назвать виновного.
- **Эмпирический фильтр взаимозависимости:** из пула 30 кандидатов оставляем только квесты,
  где детектив проходит Q1 и **валит** Q2, а медик проходит Q2 и **валит** Q1. Осталось **15**.
- Метрика: пошагово (Q1/Q2/Q3) и **полная цепь** (FULL = все три верны). Контроль `base`
  (без знаний) задаёт «пол угадывания».
- Реализация: CPU fp32 (на MPS Qwen2.5 падает — лимит 4 ГБ/тензор); всё детерминировано (seed=0).

## Результаты

### 1. Основные пайплайны (3B, 15 взаимозависимых квестов)
| Пайплайн | Q1 детектив | Q2 медицина | Q3 финал | **Полная цепь** |
|---|---|---|---|---|
| base (без знаний) — контроль | 0.00 | 0.00 | 0.00 | **0.00** |
| detective-only (отдельно) | 1.00 | 0.00 | 0.20 | **0.00** |
| medic-only (отдельно) | 0.00 | 1.00 | 0.27 | **0.00** |
| **AGENTIC (роутинг)** | 1.00 | 1.00 | 0.60 | **0.60** |
| MERGED-ties | 0.67 | 0.20 | 0.20 | **0.07** |
| MERGED-linear | 0.33 | 0.00 | 0.13 | **0.00** |

- `base` Q3 = 0.00 → финал **не угадывается** (нет конфаундера).
- Отдельные модели = 0 → у каждой только один факт (взаимозависимость доказана).
- Агент = 0.60 — лучший.

### 2. Сравнение методов слияния (3B, те же 15 квестов)
| Метод | Q1 | Q2 | Q3 | **Полная цепь** |
|---|---|---|---|---|
| **AGENTIC (роутинг)** — эталон | 1.00 | 1.00 | 0.53 | **0.53** |
| MERGED-linear | 0.33 | 0.00 | 0.20 | **0.00** |
| MERGED-TIES | 0.33 | 0.00 | 0.07 | **0.00** |
| MERGED-DARE-linear | 0.67 | 0.00 | 0.13 | **0.00** |
| MERGED-DARE-ties | 0.33 | 0.00 | 0.13 | **0.00** |
| MERGED-DELLA | 0.67 | 0.00 | 0.20 | **0.00** |
| **EMR per-step (маска под шаг)** | 1.00 | 1.00 | 0.60 | **0.60** |
| **EMR single mask (фикс.)** | 1.00 | 0.00 | 0.20 | **0.00** |

- **Все навык-агностичные слияния** (linear/TIES/DARE/DELLA): **Q2 = 0.00** (навык медика
  разрушен), полная цепь = 0.
- **EMR** сохраняет оба навыка и решает 0.60 — **только** в режиме per-step маски (= роутинг);
  с одной фиксированной маской падает до 0.00. Значит успех EMR целиком из task-conditional
  выбора, а не из «единой модели».
- (Агент 0.53 здесь vs 0.60 в табл. 1 — разница в 1 квест из 15, шум малой выборки.)

### 3. Контроль: Q3 при ПОДАННЫХ правильных фактах (изолируем рассуждение)
| Модель | Q3 при правильных фактах |
|---|---|
| base (без знаний) | 0.60 |
| detective adapter | 0.73 |
| MERGED-linear | 0.60 |
| MERGED-ties | 0.53 |
| MERGED-DARE-linear | 0.67 |
| MERGED-DARE-ties | 0.60 |
| MERGED-DELLA | 0.53 |

Получив **верные факты**, слитые модели находят виновного на 0.53–0.67 — **как база (0.60)**.
Значит **слияние НЕ ломает рассуждение** — оно ломает **припоминание узкого факта** (Q2 в
пайплайне = 0.00). Полная цепь merged = 0 из-за **потери знания**, а не неспособности сводить факты.

## Выводы
1. **Co-existence ≠ integration.** Training-free слияние не даёт единой модели, интегрирующей
   навыки на взаимозависимой задаче.
2. **Универсально по методам.** Проверены 6 методов (incl. SOTA **EMR, NeurIPS-2024**) — все
   навык-агностичные слияния проваливаются; EMR «работает» лишь как маршрутизация.
3. **Механизм.** Слияние сохраняет общее рассуждение, но **вымывает узкое выученное знание**
   (пример DELLA: яд назвала, но потеряла «доступ у механика» → взяла высокого не-механика).
4. **Scaling.** Агент растёт с моделью (1.5B ~0.44 → 3B ~0.6), merged остаётся ~0 — разрыв с
   масштабом не закрывается.

## Новизна и позиционирование
Вклад — **протокол оценки** (взаимозависимый цепной квест + мультиагент-baseline + контроли),
а не новый метод слияния. Отстройка: Task Arithmetic (Ilharco 2022 — арифметика в весах),
ARM-2026 (слияние агентов, но по отдельным бенчмаркам), Tam-2025 (composition из ортогональных
осей), EMR (arXiv:2405.17461 — task-conditional маски).

## Ограничения
Малая модель (3B) → абсолютный Q3 ~0.5–0.6 (предел рассуждения, не разрыв логики); 15 квестов;
одна пара доменов; exact-match скоринг строг (усиливает видимую деградацию). Это границы
применимости; контраст agent ↔ merged устойчив.

## Файлы и воспроизведение
```
make_datasets.py          реальные узкие знания + пул из 30 кандидатов-квестов (7 подозреваемых)
train.py                  два LoRA-адаптера (detective / medic) на общей базе
evaluate.py               фильтр взаимозависимости + base/separate/agentic/merged, метрики
evaluate_merges.py        свип методов: linear/TIES/DARE/DELLA/EMR(per-step,single) + агент
data/  kept_quest_ids.json  results_summary.json  results_full.json  results_merge_methods.json
```
```bash
pip install -r ../requirements.txt
python3 make_datasets.py && python3 train.py     # обучение на CPU
python3 evaluate.py                              # основные пайплайны + фильтр
python3 evaluate_merges.py                       # свип методов слияния (реюз kept_quest_ids)
```
Модель `Qwen/Qwen2.5-3B-Instruct`, CPU fp32, LoRA r=16 на q/k/v/o_proj (~29 МБ/адаптер), seed=0.
