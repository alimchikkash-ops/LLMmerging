# LLMmerging — слияние нейросетей без обучения: интеграция навыков vs мультиагент

> Эксперименты: **Qwen2.5-3B-Instruct**, CPU fp32, всё детерминировано (seed=0).
> Детали главного эксперимента — в [`DetectiveMerg/README.md`](DetectiveMerg/README.md);
> обзор и критерии — в [`docs/`](docs/).

## Аннотация

**Тема.** Можно ли объединить две специализированные нейросети в одну **без дообучения и
дистилляции** (training-free weight merging), чтобы она обладала навыками обеих — и заменяет ли
такая модель **мультиагентную систему** на задаче, где навыки нужно **сцеплять**?

**Мои первые эксперименты.** Усреднение весов линейных регрессий и малых MLP (`tanh`/`ReLU`),
сравнение слияния с обучением на объединённых данных, влияние общего `random_state`, выравнивание
нейронов по активациям (`ITMO_practice*.ipynb`, `notebooks/01`). Результаты рабочие, **но честно:
бóльшая часть уже придумана до меня** — усреднение весов это Model Soups (2022), соответствие
нейронов — Git Re-Basin (2022), роль инициализации — Linear Mode Connectivity (2020). Это освоение
темы и воспроизведение, а не новизна.

**Главный вклад (DetectiveMerg).** Существующие работы по слиянию меряют навыки **по отдельности**;
никто не проверяет **интеграцию навыков на взаимозависимой задаче** и не сравнивает слитую модель с
**мультиагентом** тех же специалистов. Я построил такой протокол: детективный квест из 3
взаимозависимых шагов (вывод детектива → факт от медика → финальный вывод) на **реальных, но узких**
знаниях (судебная токсикология + криминалистическая дедукция), с **эмпирическим отбором** кейсов,
доказывающим взаимозависимость, отдельными метриками сохранения навыков **S1/S2** и контролем `base`.

**Главный результат.** Правильное слияние **DARE-TIES** сохраняет **оба** навыка (S1=S2=1.00) и на
взаимозависимом квесте решает задачу **наравне с мультиагентом** (полная цепь **0.53 = 0.53**).
**Решает метод слияния:** методы, теряющие навык, проигрывают пропорционально (TIES 0.35, DELLA 0.23,
linear — рушит навык медика). По развёртыванию слитая модель — **самая компактная** (одна модель,
без адаптеров и роутинга). SOTA-метод **EMR** сохраняет навыки лишь как **task-conditional выбор
маски = маршрутизация**, а по памяти проигрывает merge.

**Значимость и планы.** Вывод практичный: с верным методом (DARE-TIES) **одна слитая модель заменяет
мультиагент** — дешевле в развёртывании (12.4 vs до 24.8 ГБ у полномодельного мультиагента) и проще
операционно. Дальше — больше пар доменов и квестов, свип методов (SLERP, EMR-auto), препринт/воркшоп.

## Проблематика
Объединять способности моделей дорого: ансамбль (несколько проходов) или дообучение/дистилляция
(compute + данные + забывание). Training-free merging обещает «бесплатное» объединение (горячая тема,
mergekit). Но успех меряют **средней точностью на независимых задачах** и не проверяют, **сцепляются**
ли навыки в одной взаимозависимой задаче и заменяет ли merge мультиагент.

## Постановка задачи
- **Вопрос:** заменяет ли training-free слияние двух специалистов мультиагентную систему на
  взаимозависимой задаче, требующей чередования обоих навыков?
- **Гипотеза (проверена):** результат зависит от **метода слияния**; метод, сохраняющий оба навыка,
  на такой задаче не уступает мультиагенту.

## Описание технического решения
- База `Qwen2.5-3B-Instruct`; два специалиста — **LoRA-адаптеры на одной базе** (детектив / медик),
  на реальных узких знаниях.
- **Квест** из 3 взаимозависимых шагов; логика по 7 подозреваемым (4 — нужная профессия, 4 — нужный
  признак, пересечение = 1 виновный) → виновный определим только при **обоих** навыках.
- **Эмпирический фильтр** взаимозависимости + контроль `base` (пол угадывания) + метрики **S1/S2**
  (сохранение навыка детектива / медика).
- Сравнение: 2 модели по отдельности / **агент с роутингом** / **слияние** (linear, TIES, DARE-TIES,
  DELLA — на полной ΔW, как в статьях) / **EMR**.
- CPU fp32 (на MPS Qwen2.5 падает — лимит 4 ГБ/тензор).

## Полученные результаты (3B, 40 квестов)
| Модель / пайплайн | S1 детектив | S2 медик | Квест (полная цепь) |
|---|---|---|---|
| detective adapter | 1.00 | 0.00 | — |
| medic adapter | 0.00 | 1.00 | — |
| **AGENTIC (роутинг)** | — | — | **0.53** |
| **MERGED-DARE-TIES** | **1.00** | **1.00** | **0.53** |
| MERGED-TIES | 0.71 | 1.00 | 0.35 |
| MERGED-DELLA | 0.71 | 0.57 | 0.23 |
| MERGED-linear | 0.71 | 0.14 | низко |

**Эффективность (CPU):** на квест ~13 с (merge-dare_ties) ≈ ~14 с (агент); развёртываемая память —
merged **12.4 ГБ** (одна модель) < мультиагент-LoRA 12.46 < EMR 13.85 < наивный мультиагент 24.8 ГБ.
Контроль: `base` без знаний проходит полную цепь ≈ 0 (финал не угадывается).

**Вывод:** при верном методе (DARE-TIES) слитая модель **сохраняет оба навыка и интегрирует их
наравне с мультиагентом**, оставаясь самой компактной для развёртывания. Метод слияния — решающий.

## Ограничения
Модель 3B → абсолютный финал ~0.5 (предел рассуждения; при поданных явных фактах ~0.7); 40 квестов
над 14 комбо, одна пара доменов; exact-match скоринг строг. Это границы применимости, не опровержение.
